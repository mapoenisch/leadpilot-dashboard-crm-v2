  kein Demopasswort im Produktpfad.

## PR-RLS-02 — öffentliche Reads und fehlende Organisationsgrenze in RLS

- **Status:** GREEN seit G45 · **Zielgate:** G45 · **Runner:** Vitest
- **Ursache:** `supabase/schema.sql` vergibt `FOR SELECT USING (true)` auf
  `companies`, `contacts`, `imported_funnel_deals`; keine Tabelle trägt
  `organization_id`, kein Mandanten-`USING`/`WITH CHECK` existiert.
- **Reproduzierender Test:** `src/review/acceptance/security.acceptance.ts`
  (`[PR-RLS-02] begrenzt Reads auf die eigene Organisation`).
- **Aktueller Nachweis:** Je Tabelle fehlen eigene `organization_id`-Spalte,
  `auth.uid()`-Bindung, Mitgliedschafts-/Rollenprüfung und exklusive
  Org-Policies (offene `USING (true)`-Reads bestehen).
- **Zielauftrag:** 067B · **Abnahme:** `organization_id` + RLS je
  Mandantentabelle, Policies an `auth.uid()` und aktive Mitgliedschaft/Rolle
  gebunden, kein `USING (true)`/`WITH CHECK (true)`.

## PR-INGEST-03 — n8n-Ingress ohne HMAC, Timestamp und Nonce

- **Status:** GREEN seit G46 · **Zielgate:** G46 · **Runner:** Vitest
- **Ursache:** `tools/n8n/live-kpi-ingest.workflow.json` geht vom Webhook
  direkt zum Postgres-Node (`Execute Ingest RPC`); kein Node prüft Timestamp,
  Nonce oder eine HMAC-Signatur über `timestamp + '.' + nonce + '.' + rawBody`.
- **Reproduzierender Test:** `src/review/acceptance/security.acceptance.ts`
  (`[PR-INGEST-03] weist unsignierte Ingress-Anfragen ab`).
- **Aktueller Nachweis:** Der einzige Webhook→DB-Pfad im Verbindungsgraph
  enthält keinen Guard-Node; Timestamp-/Nonce-/HMAC-Prüfung fehlt.
- **Zielauftrag:** 067C · **Abnahme:** Guard-Node auf jedem Webhook→DB-Pfad,
  HMAC-Prüfung vor jedem Postgres-Node, Replay-Schutz, Fehlercodes
  `INGEST_SIGNATURE_INVALID`/`INGEST_REPLAY_DETECTED`.
